# Superpowers Planning With Files 示例

## 首次进入一个新项目时

如果仓库里还没有 `docs/planning/`，主 Agent 应先初始化：

1. 创建 `docs/planning/`
2. 创建 `docs/planning/current.md`
3. 创建 `docs/planning/decisions.md`
4. 在 `current.md` 中先写入主目标、成功定义、当前阶段、下一步唯一动作

## `docs/planning/current.md` 最小起步示例

```md
# 当前规划状态

## 主目标

为当前项目实现用户登录流程。

## 成功定义

用户可以完成登录，关键路径有自动化测试覆盖。

## 非目标

本阶段不处理注册、找回密码、社交登录。

## 当前阶段

设计

## 当前正在做

梳理登录流程的页面、接口与状态流。

## 已完成里程碑

- 已确认登录属于当前主线功能

## 当前阻塞

- 尚未确认是否复用现有 session 方案

## 活跃支线

- 无

## 下一步唯一动作

阅读现有认证相关代码，确认登录状态存储方式。

## 恢复提示

如果会话中断，先看主目标、当前阻塞和下一步唯一动作，再继续推进。
```

## `docs/planning/decisions.md` 最小起步示例

```md
# 关键决策记录

## 记录模板

### 2026-03-22 - 登录态沿用现有 session 方案

- 日期：2026-03-22
- 决策内容：登录态继续使用现有 session 机制，不新增 JWT 体系。
- 决策原因：当前项目已有 session 中间件与鉴权流程，扩展成本最低。
- 影响范围：后续登录、登出、鉴权接口与测试实现。
```

## 插入支线任务时怎么处理

如果用户临时要求“顺手修一下 README 的错字”：

- 不改 `主目标`
- 在 `活跃支线` 登记这项支线
- 支线完成后移除该登记
- 把 `下一步唯一动作` 恢复回主线动作
